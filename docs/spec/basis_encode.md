# Basis Universal encoders (`ktxTexture2_CompressBasisEx`)

Goal: pure Rust port of the basisu encoder paths reachable from libktx `basis_encode.cpp`:
BasisLZ/ETC1S, UASTC LDR 4x4 (+RDO), UASTC HDR 4x4 and UASTC HDR 6x6 intermediate, driven by
`basis_compressor` (`basisu_comp.cpp`). Reference build: libktx on x86_64 compiles basisu with
`-msse4.1 -DBASISU_SUPPORT_SSE=1` (CMake `BASISU_SSE` defaults ON), no OpenCL, so the goldens
link `scripts/golden/build_basisu_encoder.sh` (`$WORK/libbasisu_enc.a`) with that config.

Port order (each stage bit exact vs. the C++ build before the next one starts):
1. [x] `basisu_etc.cpp` ETC1 block encoder (`src/basisu/etc_enc.rs`)
2. [x] UASTC LDR 4x4: `basisu_bc7enc.cpp` (`src/basisu/bc7enc.rs`), block encoder
   (`basisu_uastc_enc.cpp` `encode_uastc`, `src/basisu/uastc_enc.rs`), RDO (`uastc_rdo`)
3. [x] ETC1S: vector quantizer (`basisu_enc.h` `tree_vector_quant`, `src/basisu/vq.rs`),
   frontend (`basisu_frontend.cpp`, `src/basisu/frontend.rs`), Huffman encoder
   (`src/basisu/huffman_enc.rs`), backend (`basisu_backend.cpp`, `src/basisu/backend.rs`)
4. [x] `basis_compressor` pipeline (`basisu_comp.cpp`, `basisu_basis_file.cpp`,
   `src/basisu/comp.rs`, `basis_file.rs`) and libktx `basis_encode.cpp` (`src/basis_encode.rs`)
5. [x] UASTC HDR 4x4 (`basisu_uastc_hdr_4x4_enc.cpp` -> `src/basisu/uastc_hdr_4x4_enc.rs`,
   CEM 7 / 11 single plane parts of `basisu_astc_hdr_common.cpp` -> `src/basisu/astc_hdr_enc.rs`)
6. [x] UASTC HDR 6x6 intermediate (`basisu_astc_hdr_6x6_enc.cpp` -> `src/basisu/astc_hdr_6x6_enc.rs`,
   6x6 paths of `basisu_astc_hdr_common.cpp`)

## Shared helpers (`basisu::enc`)

`color_rgba` as `[u8; 4]` with clamping / no-clamp constructors, `color_distance` (perceptual
14/45/5 luma, 26/3 chroma weights, u32 wrap as in C; linear squared distance), `hash_hsieh`,
`indirect_sort` / `std_sort_by`: a port of libstdc++ `std::sort` (introsort, median of three,
heapsort fallback, 16 element final insertion sort) so ties come out in the C++ order
(`eliminate_redundant_or_empty_endpoint_clusters` merges equal clusters in that order).

## ETC1 encoder (`basisu::etc_enc`)

`etc_block` (`EtcBlock`, big endian bit layout, all pack/unpack/selector helpers),
`unpack_etc1`, `etc1_optimizer` (cluster fit with `g_cluster_fit_order_tab`, neighborhood scan +
refinement, Bloom filter of tried colors via `hash_hsieh`, slow/fast evaluators incl. the
`g_eval_dist_tables` skip for medium quality and the luma sorted fast classifier),
`pack_etc1_block_solid_color` (`g_etc1_inverse_lookup` built once via `OnceLock`),
`pack_eac_a8`. Tables generated by `scripts/gen_basisu_etc_tables.py` into `etc_enc_tables.rs`.
- The SSE 4.1 kernels (`find_selectors_*`, `*_distance_rgb_4_N`) compute the same int32
  distances and only differ in early-out granularity, which never changes accepted solutions;
  the scalar path is ported.
- C++ quirk kept: `etc1_optimizer::params::m_use_color4` shadows the base
  `basis_etc1_pack_params::m_use_color4` (`Etc1OptimizerParams::use_color4` vs `pack.use_color4`).
- `init`/`compute` take the params explicitly (no stored `m_pParams`/`m_pResult` pointers);
  `results::m_pSelectors` becomes an owned `Vec<u8>` (resized to `n` when shorter).
Tests: `tests/basisu_etc.rs` vs `scripts/golden/gen_basisu_etc_golden.sh` (3000 blocks x 64
optimizer configs: quality, perceptual, cluster fit, color4, 8/16 pixels, scan deltas, base
color constraint, forced selectors, refinement; block helpers on results and random blocks;
solid color; EAC A8).

## bc7enc (`basisu::bc7enc`)

`color_cell_compression` (PCA endpoints, least squares refinement, uber levels 1..4, single
color fallbacks for BC7 mode 1 and ASTC 4-bit 3-bit, 4-bit 2-bit RGBA, range 7/13 2-bit, range
11 5-bit), `color_cell_compression_est_astc`, the `g_*_weights*x` least squares tables and
`bc7enc_compress_block_init` tables (`bc7enc_tables()`, built once via `OnceLock`).
- `color_cell_compressor_results::m_pSelectors/_temp` become owned `[u8; 16]` arrays; the
  single color packers return their selector index and the caller fills the arrays.
- Float semantics follow the SSE build (no FMA contraction): f32 math, f64 normal equations
  with f32 products accumulated, `(int)` truncation; u32 wrapping in weighted distances.
- `check_best_overall_error` is `_DEBUG` only in C++ and not ported.
Tests: `tests/basisu_bc7enc.rs` vs `scripts/golden/gen_basisu_bc7enc_golden.sh` (1400 blocks x
16 range/mode configs x 12 variants: perceptual, uber level, least squares passes, pixel count,
forced selectors; `est_astc` over 6 weight tables, 3/4 comps, weights, early out).

## UASTC LDR 4x4 encoder (`basisu::uastc_enc`)

`encode_uastc` (levels fastest..very slow, favor UASTC/BC7 error, ETC1 hint flags, favor simpler
modes), all 19 mode encoders, `pack_uastc` (Huffman mode, hints, BISE endpoints, anchor weight
inversion), BC1 hint selection (`encode_bc1` + `transcode_uastc_to_bc1_hint0/1`), ETC1 hint
search (flip estimate, sorted bias table, YCbCr error) and `uastc_pack_eac_a8`.
Decoders needed for the error checks: `unpack_bc1` and `bc7u::unpack_bc7` (`basisu::gpu_texture`).
- The repeated C++ mode functions are folded: one subset modes (0, 1, 5, 10, 12, 14, 18), 2
  subset RGB (2, 4), dual plane (6, 11, 13, 17); per mode tables keep the C++ constants.
- `results[MAX_ENCODE_RESULTS]` becomes a capped `Vec`; `BASISU_VALIDATE_UASTC_ENC` (debug only)
  checks are not ported.
Tests: `tests/basisu_uastc_enc.rs` vs `scripts/golden/gen_basisu_uastc_enc_golden.sh` (3000
blocks incl. LA and near opaque kinds x levels 0..4 + 6 flag variants; random BC1 / BC7 decode).

## UASTC RDO (`basisu::uastc_enc::uastc_rdo`)

`uastc_rdo` / `uastc_rdo_blocks` (selector bit pattern copying from the previous
`lz_dict_size / 16` blocks, smooth block error scale, skip threshold, literal / tdefl match cost
estimate, mode 0 endpoint refinement with forced selectors), `uastc_recompute_hints`.
- `selector_history` (`std::unordered_map`, never iterated) becomes a `HashMap<(ofs, sel), u32>`.
- The job pool split (`num_blocks / total_jobs` independent ranges, each with its own history)
  runs on `std::thread::scope`; output depends only on `total_jobs`. Returns `(ok, stats)`; the
  stats are the C++ `debug_printf` counters.
- `tdefl` distance extra bit tables are computed in `const` instead of listed.
Tests: `tests/basisu_uastc_rdo.rs` vs `scripts/golden/gen_basisu_uastc_rdo_golden.sh` (11
generated 96x64 images incl. alpha, high noise and tiled ones x 16 configs: lambda, dict size,
literal cost, RMS ratio / skip threshold, smooth block params, refinement, levels and hint flags
for the recompute, 1 / 4 / 7 jobs).

## Vector quantizer (`basisu::vq`)

`priority_queue`, `tree_vector_quant<vec<N, float>>` (`generate`, the three `retrieve`
overloads as `retrieve` / `retrieve_origins` / `retrieve_max`, PCA split axis, k-means refine,
unsplittable node fallbacks), `compute_pca_from_covar`, `generate_hierarchical_codebook_threaded`
(+ `_internal`).
- `std::map<vec, weighted_block_group>` becomes a `BTreeMap` keyed by `vec::operator<`
  (lexicographic, `-0.0 == 0.0`), so unique vector order matches.
- The SSE 4.1 `update_covar_matrix_16x16` kernel evaluates the same per element products as the
  scalar loop; only the scalar loop is ported. The job pool clusterizers (>= 262144 unique
  vectors) run on `std::thread::scope`.
- C++ quirk kept: the `prep_split` fallback sorts along the largest axis but splits in unsorted
  order (sorted indices unused).
Tests: `tests/basisu_vq.rs` vs `scripts/golden/gen_basisu_vq_golden.sh` (6 vector kinds incl.
duplicates, signed zeros and 1e-7 perturbations x 7 sizes x 5 codebook sizes, weights, parent
codebooks, even/odd pairs, N = 6 and 16; threaded path on 270000 unique vectors).

## ETC1S frontend (`basisu::frontend`)

`basisu_frontend` (`init`, `compress`, getters, `reoptimize_remapped_endpoints`): initial ETC1S
blocks, endpoint training vectors and TSVQ clusterization (hierarchical parents), endpoint
codebook / refinement / new cluster introduction / redundant cluster elimination, selector
clusterization, optimized selector codebook, per block selector search (lower bound early outs,
duplicate block shortcut per 2048 block job), flat selector clusters, endpoint refinement given
selectors (levels >= 4 and video), validation checks.
- Jobs are run in order; only `find_optimal_selector_clusters_for_each_block` depends on the C++
  job split (2048 blocks) and keeps it. `max_threads` for the codebooks follows C++
  (`multithreaded ? min(hw threads, 8, job pool threads) : 0`).
- `find_lowest_error_*_rgb_4_N_sse41` early out with a partial sum above the best error just
  like the scalar loop, so the scalar loop is ported.
- Not ported: OpenCL paths, `init_global_codebooks` (libktx never passes global codebooks), the
  debug image dumps. `BASISU_FRONTEND_VERIFY` aborts in C++; here `compress` returns false.
- C++ quirk kept: `compute_endpoint_subblock_error_vec` passes `scaled = true` for an unscaled
  color to `get_block_colors5`.
Tests: `tests/basisu_frontend.rs` vs `scripts/golden/gen_basisu_frontend_golden.sh` (12 images
of 64..2560 blocks incl. noise, duplicate blocks and flat areas x 12 configs: levels 0..6,
perceptual / linear, 16..2000 clusters, video frames, disabled hierarchy, validation; then
`reoptimize_remapped_endpoints` with and without final codebook optimization) and libstdc++
`std::sort` tie order (40 key sets). Unkilled mutations are error ties (`>=` vs `>` in the
flat selector and step >= 1 endpoint acceptance) and equivalent early outs.

## Huffman encoder (`basisu::huffman_enc`)

`histogram`, `canonical_huffman_*` (radix sort, Moffat-Katajainen in place code lengths, max code
size enforcement), `huffman_encoding_table` (u16 / u32 frequencies, u32 rescaled to 16 bits),
`bitwise_coder` (bits, codes, truncated binary, Rice, VLC, append, `emit_huffman_table` with
zero / repeat run codes), `palette_index_reorderer` (optional distance callback as `&dyn Fn`).
- `canonical_huffman_radix_sort_syms` returns which of the two buffers holds the result instead
  of a pointer. `huff2D` is not ported (unused by the libktx paths).
Tests: `tests/basisu_huffman_enc.rs` vs `scripts/golden/gen_basisu_huffman_enc_golden.sh` (88
histogram shapes incl. Fibonacci, sparse, > 16 bit and single symbol x max code sizes 7..17;
200 random coder op sequences; 120 reorder index streams with and without distance weights).

## ETC1S backend (`basisu::backend`)

`basisu_backend` (`init`, `encode`, `get_output`): endpoint / selector palettes, endpoint
prediction (left, upper, upper left or video CR) with endpoint RDO, palette index reordering and
`reoptimize_remapped_endpoints`, selector codebook hamming ordering, selector history buffer RDO
with RLE, slice CRC16s, Huffman coded slice data, endpoint and selector codebooks (raw fallback).
- `encode(&mut frontend)` takes the frontend instead of storing `m_pFront_end` in `init`.
- The reference x86 build takes the `g_cpu_supports_sse41` endpoint RDO path: trial endpoints
  are scored with the block's own selectors (`*_distance_rgb_4_N_sse41`); its early out only fires
  once the sum reaches the best error, so a full sum is equivalent. The non SSE path is not ported.
- `BASISU_BACKEND_VERIFY` aborts in C++; here `encode` returns 0. Debug prints / images skipped.
- `basist::crc16` lives in `basisu::enc`; `approx_move_to_front::reset` added to the transcoder's
  port.
Tests: `tests/basisu_backend.rs` vs `scripts/golden/gen_basisu_backend_golden.sh` (12 images of
8x8..33x20 blocks incl. odd sizes x single slice, two mip slices, three video frames x 13
configs: levels 0..6, endpoint / selector RDO thresholds 0..10, perceptual / linear, 16..2000
clusters; 312 cases hashing every output buffer and CRC).

## basis_compressor (`basisu::comp`, `basisu::basis_file`)

`basis_compressor` (`init`, `process`, `get_output_basis_file`) for caller supplied LDR images:
swizzle, alpha detection (`m_check_for_alpha` / `m_force_alpha`), ETC1S RGB + alpha slice
split, block padding (`crop_dup_borders`), slice descriptors and sanity / texture type checks,
source block extraction, ETC1S quality level -> cluster counts and RDO threshold scaling,
frontend + backend, UASTC LDR 4x4 block encode + optional RDO; `basisu_file` writes the packed
77 byte header, 23 byte slice descriptors, codebooks, tables, slice data and CRC16s. Minimal
`basisu::image` (`Image`), `param<T>` (`Param`: clamped on assignment, `was_changed`).
- Not ported (unreachable from libktx): file / DDS / alpha file loading, resampling, y flip,
  renormalization, mipmap generation, user mipmap chains, stats and transcode validation,
  KTX2 output, debug images, OpenCL. Those options make `process` fail instead.
- UASTC jobs (256 blocks each, independent) run in order; the RDO job count follows C++
  (`m_rdo_uastc_ldr_4x4_multithreading ? min(4, pool threads) : 0`).
- HDR / XUASTC modes return `cECFailedEncodeUASTC` until stages 5 and 6.
Tests: `tests/basisu_comp.rs` vs `scripts/golden/gen_basisu_comp_golden.sh` (13 inputs: single
images 1x1..128x96, image arrays of halving sizes, video frames, 2D arrays, alpha in some or all
images, one 254 alpha pixel x 28 configs: ETC1S quality 1..255 / explicit clusters / levels
0..6 / RDO flags and thresholds / swizzles / force and no alpha check, UASTC levels and flags,
RDO lambda, dict size, smooth block params, 1 and 4 threads; 364 cases hashing the error code
and the .basis file). Unkilled mutations: quality 223 vs 192 RDO scaling (codebooks are
near-lossless there), the quality 129 boundary (equivalent: the scale is 1.0) and the 64 / 96
cluster minimums (only reached with fewer blocks than clusters).

## ASTC HDR 6x6 encoder (`astc_hdr_6x6_enc::compress_photo`)

`compress_strip_task` (per block: three source passes (original, Gaussian 1.45 / 1.83), block
