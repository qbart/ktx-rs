# Basis Universal encoders (`ktxTexture2_CompressBasisEx`)

Goal: pure Rust port of the basisu encoder paths reachable from libktx `basis_encode.cpp`:
BasisLZ/ETC1S, UASTC LDR 4x4 (+RDO), UASTC HDR 4x4 and UASTC HDR 6x6 intermediate, driven by
`basis_compressor` (`basisu_comp.cpp`). Reference build: libktx on x86_64 compiles basisu with
`-msse4.1 -DBASISU_SUPPORT_SSE=1` (CMake `BASISU_SSE` defaults ON), no OpenCL, so the goldens
link `scripts/golden/build_basisu_encoder.sh` (`$WORK/libbasisu_enc.a`) with that config.

Port order (each stage bit exact vs. the C++ build before the next one starts):
1. [x] `basisu_etc.cpp` ETC1 block encoder (`src/basisu/etc_enc.rs`)
2. [ ] UASTC LDR 4x4 block encoder (`basisu_uastc_enc.cpp`, needs `basisu_bc7enc.cpp`) + RDO
3. [ ] ETC1S frontend (`basisu_frontend.cpp`: VQ, clusterization) + backend (`basisu_backend.cpp`:
   endpoint/selector palettes, Huffman) + KTX2 BasisLZ global data
4. [ ] `basis_compressor` pipeline (`basisu_comp.cpp`) and libktx `basis_encode.cpp`
5. [ ] UASTC HDR 4x4 (`basisu_uastc_hdr_4x4_enc.cpp`, `basisu_astc_hdr_common.cpp`)
6. [ ] UASTC HDR 6x6 intermediate (`basisu_astc_hdr_6x6_enc.cpp`)

## Shared helpers (`basisu::enc`)

`color_rgba` as `[u8; 4]` with clamping / no-clamp constructors, `color_distance` (perceptual
14/45/5 luma, 26/3 chroma weights, u32 wrap as in C; linear squared distance), `hash_hsieh`,
`indirect_sort` (C++ uses unstable `std::sort`; current callers only depend on key order).

## ETC1 encoder (`basisu::etc_enc`)

`etc_block` (`EtcBlock`, big endian bit layout, all pack/unpack/selector helpers),
`unpack_etc1`, `etc1_optimizer` (cluster fit with `g_cluster_fit_order_tab`, neighborhood scan +
refinement, Bloom filter of tried colors via `hash_hsieh`, slow/fast evaluators incl. the
`g_eval_dist_tables` skip for medium quality and the luma sorted fast classifier),
`pack_etc1_block_solid_color` (`g_etc1_inverse_lookup` built once via `OnceLock`),
`pack_eac_a8`. Tables generated by `scripts/gen_basisu_etc_tables.py` into `etc_enc_tables.rs`.
- The SSE 4.1 kernels (`find_selectors_*`, `*_distance_rgb_4_N`) compute the same int32
  distances and only differ in early-out granularity, which never changes accepted solutions;
  the scalar path is ported.
- C++ quirk kept: `etc1_optimizer::params::m_use_color4` shadows the base
  `basis_etc1_pack_params::m_use_color4` (`Etc1OptimizerParams::use_color4` vs `pack.use_color4`).
- `init`/`compute` take the params explicitly (no stored `m_pParams`/`m_pResult` pointers);
  `results::m_pSelectors` becomes an owned `Vec<u8>` (resized to `n` when shorter).
Tests: `tests/basisu_etc.rs` vs `scripts/golden/gen_basisu_etc_golden.sh` (3000 blocks x 64
optimizer configs: quality, perceptual, cluster fit, color4, 8/16 pixels, scan deltas, base
color constraint, forced selectors, refinement; block helpers on results and random blocks;
solid color; EAC A8).
